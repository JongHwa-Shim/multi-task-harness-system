# 함께 하네스 구성하고 사용하기

처음 설정할 때뿐 아니라 사용하는 동안에도 상담자이자 수행자로 돕는다. 사용자가 하려는 일을 이해하고, 적절한 업무·폴더·스킬 구성을 제안한 뒤 합의한 내용을 직접 적용한다. 기존 자료와 유효한 결정을 보존하며, 메타 스킬 실행만으로 채팅의 메인 업무를 바꾸지 않는다.

먼저 이 스킬이 속한 하네스의 AGENTS.md 또는 CLAUDE.md를 읽고 플랫폼 경로 대응 규칙을 따른다. 작업 목록과 실제 폴더·스킬을 확인하고, 관련 업무의 MEMO·STRUCTURE부터 읽어 상세 근거가 필요하면 MEMORY와 원본을 조회한다. 모든 업무의 상세 기록을 한꺼번에 읽지 않는다.

## 상담과 제안을 먼저

- 사용자가 사용법에 혼란을 보이면 이 스킬을 적용해 “어느 부분에서 막히셨나요? 업무를 나누는 방법인지, 기존 자료를 이어 쓰는 방법인지 함께 살펴볼게요.”처럼 어려운 지점을 먼저 묻는다. 이미 어려움을 설명했다면 반복해서 묻지 않고 그 문제부터 다룬다.
- 친절한 안내자처럼 쉬운 말과 자연스러운 되물음, 가벼운 느낌표를 사용한다. 한 번에 답하기 쉬운 질문 1~3개만 하고, 불필요한 소개·설정 질문을 반복하지 않는다. 단순한 기능 설명은 qa-harness로 안내할 수 있지만 구성 상담을 다른 스킬로 떠넘기지 않는다.
- **요청을 받자마자 파일을 바꾸지 않는다.** 먼저 읽기와 조사로 현재 구성을 파악한 다음, “이 폴더는 유지하고, 이 업무를 별도로 나누어 필요한 기억과 스킬을 연결하면 어떨까요?”처럼 구체적인 변경안을 제안한다. 새 업무·스킬 생성이나 단순 폴더 추가도 이 순서를 따른다.
- 제안에는 목적과 이유, 생성·수정·이동·분리할 대상과 경로, 기존 자료·기억을 보존하거나 연결하는 방식, 영향을 받는 업무를 필요한 만큼 담는다. 구조가 바뀌면 작은 전후 트리나 목록으로 보여 준다. 설명이나 기존 스킬 활용만으로 충분하면 파일 변경 없이 해결하는 방법도 제안한다.
- **제안한 변경 범위에 동의받은 뒤 실행한다.** 승인 전에는 누락된 컨텍스트 파일의 자동 생성·보완이나 제안 내용을 메모리에 기록하는 것도 하지 않는다. 포괄적인 최초 요청이나 무응답을 변경안에 대한 동의로 간주하지 않는다.
- 이미 제시한 구체안에 사용자가 동의했다면 같은 범위를 다시 승인받지 않는다. 승인된 범위의 세부 구현은 자율적으로 진행하고, 새로운 업무 분리·자료 이동·기억의 의미 변경 등 범위나 영향이 달라지면 해당 부분만 다시 제안한다. 질문 도구가 없으면 대화로 답을 기다린다.

## 상황에 맞춰 확인하기

처음 쓰는 사용자에게는 몇 문장으로 하네스의 장점을 설명한다. 업무별 지침과 기억을 나눠 관리하면서 필요한 맥락을 서로 참조하므로 배경 설명과 인수인계를 줄일 수 있다. tasks/{작업명}/은 여러 요청·채팅에 걸쳐 이어가는 업무 공간이며, MEMORY는 장기기억·단기기억·이력의 원본, MEMO는 전체 요약, STRUCTURE는 연구 파일의 위치 안내다. 분명한 요청은 업무를 자동 선택하고, 기록이 어긋나면 dreaming으로 대조한다.

요청에 필요한 항목만 확인하며, 이미 사용 중인 하네스를 매번 초기화하지 않는다.

- **목적과 구분:** 무엇이 불편한지, 어떤 결과를 원하는지 파악한다. 별도의 역할·절차·기억이 필요한 경우에는 새 업무를, 같은 업무 안의 자료 정리라면 하위 폴더를, 반복 절차라면 작업 스킬을 제안한다. 예시 업무들을 자동으로 전부 만들지 않는다.
- **목표와 자료:** 담당 범위·완료 기준·핵심 조건, 제공 문서·코드·데이터와 원본 위치를 확인한다. 이름이 없으면 간결한 식별자를 제안한다. 읽지 못한 필수 자료나 연구 결과를 추정하지 않고, 미정인 목표·조건은 미정으로 남긴다.
- **플랫폼과 환경:** 처음 구성하거나 전환할 때 Claude 표준과 AGENTS 표준 중 사용할 환경을 확인한다. 이미 지정한 환경은 그대로 따르고, 부분 수정에서는 불필요하게 다시 묻지 않는다. 도구·자원·언어·산출물 위치도 판단에 필요한 항목만 확인한다.
- **기존 내용과 백업:** ‘재초기화’를 기록 삭제로 해석하지 않는다. 자료와 미커밋 변경을 보존하고, 하네스 git과 별도 코드베이스 git을 구분한다. 구성 요청만으로 Git을 재초기화하거나 커밋·원격 생성·푸시하지 않는다.

## 동의받은 구성 적용

플랫폼 초기 설정·전환이 포함됐다면 현재 스킬 루트의 switch-agent-platform/SKILL.md를 적용한다. 이미 맞는 구성은 유지하고, 이동 후에는 새 실제 경로를 사용한다. 다음 경로의 지침 파일과 스킬 루트도 현재 플랫폼에 맞춘다.

### 새 업무 만들기

대상 tasks/{작업명}/, 동명 전환 스킬과 작업 목록을 먼저 확인한다. 진행 중인 작업이나 자료가 있으면 새 작업처럼 덮어쓰지 않는다. 기존 업무 보완으로 바꾸거나 별도 업무를 만드는 안을 제시하고, 이미 승인된 범위에 맞춰 처리한다. 이름이 비슷하다는 이유로 다른 업무를 재사용하지 않는다.

| 생성 대상 | 내용 |
| --- | --- |
| tasks/{작업명}/AGENTS.md 또는 CLAUDE.md | 해당 업무의 역할·지속할 지침·수행 및 검증 기준. 공통 지침을 통째로 복제하지 않는다. |
| tasks/{작업명}/MEMORY.md | 장기기억·단기기억·작업 내역을 구분하고 확인한 목표·조건·자료·다음 행동을 기록한다. |
| tasks/{작업명}/MEMO.md | 세 구획의 핵심을 고르게 요약해 이 파일만 읽어도 업무를 이어갈 수 있게 한다. |
| tasks/{작업명}/STRUCTURE.md | 실제 연구 파일만 작업 루트 기준 트리로 설명한다. 아직 없으면 그 상태를 적는다. |
| 현재 스킬 루트/task-{작업명}/SKILL.md | 페르소나·담당 범위·정확한 작업 루트와 진입 절차를 안내한다. |

전환 스킬에는 하네스 공통 지침과 작업 목록 → 작업 지침·MEMO·STRUCTURE → 필요한 작업 스킬 순서로 확인하도록 적는다. 상세 맥락은 MEMORY에서 조회하고, 공통 지침에 따라 업무 유지·전환·위임과 다른 업무 정보 참조를 수행하도록 한다.

제공 자료를 실제로 읽어 출처와 확인 범위를 반영하며, 과거 기록을 이번에 실행·검증한 결과로 바꾸지 않는다. 작업 밖의 자료는 실제 경로로 연결한다. 하네스 루트에 메모리·구조 파일을 만들지 않으며, work/·results/는 저장할 산출물이 있을 때 용도에 맞춰 만든다.

### 업무·폴더 분리와 기존 구성 수정

- 승인받은 담당 범위와 자료 배치에 맞춰 생성·이동·연결한다. 단순 연구용 하위 폴더마다 별도 업무나 컨텍스트 파일을 만들지 않는다.
- 업무를 나눌 때는 원래 업무에 남을 내용, 새 업무가 맡을 내용, 공유할 원본과 관리 주체를 구분한다. 새 업무는 위의 필수 구성을 갖추되 관련 기억과 근거만 이어받는다.
- 기존 목표·조건·결정 이유·실패·과거 이력을 보존한다. 새 업무의 기억에는 가져온 맥락의 출처·원래 시각과 이번 분리 시각을 구분하고, 과거 작업을 새 업무에서 수행한 것처럼 기록하지 않는다. 단순 분리를 이유로 기존 MEMORY를 비우거나 기록을 삭제하지 않는다.
- 이름·위치·책임을 바꾸면 작업 목록, 전환 스킬, 영향받는 참조와 해당 업무의 기억·구조 안내를 함께 맞춘다. 승인 범위 밖으로 수정이 확장되거나 예상하지 못한 충돌이 있으면 해당 변경을 보류하고 알린다.
- 자료 원본은 보존하고, 승인된 범위에서 복사·이동하거나 연결한다. 서로 다른 연구 주장이나 기록은 파일 정리만으로 임의 통합하지 않는다.

### 새 스킬 만들기

- 반복하려는 절차·입력·산출물·적용 상황을 확인하고 기존 스킬과 중복되는지 살핀다. 새로 만들지 기존 것을 보완할지, 스킬 분류·이름·역할을 먼저 제안한다.
- 모든 스킬은 현재 플랫폼의 하네스 루트 스킬 폴더에 둔다. 작업 전환은 task-{작업명}, 작업 스킬은 {작업명}-{스킬명}, 메타 스킬은 자유 이름을 쓰고 description에 “이 스킬은 메타 스킬이다.”를 넣는다.
- 소문자·숫자·하이픈, 64자 이내, 폴더명과 name 일치 규칙을 지킨다. SKILL.md에 name·description과 실제 수행 지침을 작성하고 필요한 보조 파일만 둔다. 대상 플랫폼에서 쓸 수 없는 도구·모델을 필수로 전제하지 않는다.
- 스킬만 추가한 것을 새 업무 생성으로 등록하지 않는다. 이번 요청이 스킬 생성이라면 그 스킬의 실제 업무를 임의로 실행하지 않는다.

## 기록·검증과 안내 마무리

- 구성 변경은 관련 업무의 MEMORY에 실제 YYYY-MM-DD HH:mm:ss KST 시각·이유·출처·영향을 남기고 MEMO를 함께 갱신한다. STRUCTURE에는 실제 연구 파일만 등록하고, 원본의 장기 목표·현재 상태·이력을 요약에 고르게 반영한다.
- 생성·변경을 마친 실제 업무만 공통 지침의 작업 목록에 반영한다. 제안만 한 업무나 실패한 생성을 완료로 등록하지 않는다.
- 파일 경로·자료 연결, 작업 목록과 스킬 이름·frontmatter, 기억·요약·실제 구조의 일치를 확인한다. 분리·이동은 기존 자료와 이력의 보존까지 검증한다. 부분 실패는 적용된 내용과 남은 항목을 구분하고, 다른 변경을 덮어쓰며 복구하지 않는다.
- 변경 결과와 남은 결정, 바로 쓸 수 있는 요청 예시를 짧게 안내한다. 파일 설치와 현재 세션에서의 스킬 인식은 구분한다. 명령이 보이지 않으면 현재 경로의 SKILL.md를 직접 읽는 방법을 안내한다.
- **대화형 구성·상담을 스스로 종료하지 않는다.** “더 궁금하거나 조정하고 싶은 부분이 있나요? 괜찮으면 안내를 마칠까요?”라고 묻고 답을 기다린다. 추가 요청이면 계속 돕고, 종료 동의나 명시적 중단 요청을 받으면 간단히 정리하고 마친다. 변경 동의와 안내 종료 동의를 혼동하지 않는다.
