# 하네스 플랫폼 전환

하네스의 운영 파일 배치를 사용자가 선택한 표준으로 맞춘다. 현재 에이전트 프로그램을 바꾸거나 새 채팅을 실행하는 작업과 구분한다. 메인 업무는 유지한다.

## 목표와 범위 확인

- 먼저 **어느 표준으로 바꿀지 확인**한다. 요청이나 init-harness의 합의에 목표가 이미 있으면 적용할 목표를 짧게 알리고 진행한다. 목표가 없으면 AGENTS 구성과 Claude 구성 중 선택하도록 질문하고, 답변 전에는 이동하지 않는다.
- 이 스킬이 속한 하네스 루트와 실제 파일 배치를 확인하고, 존재하는 공통 AGENTS.md 또는 CLAUDE.md를 읽는다. 하네스 공통 지침의 플랫폼 경로 대응 규칙을 따른다. 호스트 플랫폼과 이번 전환의 목표가 다르면 전환 파일명은 목표를 따른다.
- 작업 목록과 tasks/의 실제 구성을 대조해 하네스가 관리하는 작업 루트를 확인한다. 범위는 하네스 루트의 설정 디렉터리와 루트·작업 루트의 지침 파일이다. 내부 코드베이스·외부 자료·별도 저장소의 동명 파일은 자동 전환하지 않는다.

| 목표 | 루트·작업 루트의 지침 파일 | 하네스 루트의 설정 디렉터리 |
| --- | --- | --- |
| AGENTS 구성 | CLAUDE.md → AGENTS.md | .claude/ → .agents/ |
| Claude 구성 | AGENTS.md → CLAUDE.md | .agents/ → .claude/ |

## 이동 전 점검

- 이동할 원본과 목적지, 포함된 스킬·보조 파일을 확인한다. 기존 파일 내용과 구조를 확인할 수 있게 기록하고, 미커밋 변경도 보존한다. 소스가 없고 목표만 있으면 이미 전환된 항목으로 취급한다.
- 양쪽 설정 디렉터리가 있으면 충돌하지 않는 항목을 합칠 계획을 세운다. 같은 경로에 파일이 겹치면 내용을 비교한다. 내용이 같으면 원본이 보존되는지 확인해 중복만 정리할 수 있다. 내용이 다르거나 파일·디렉터리 유형이 충돌하면 **이동 전에** 충돌 목록을 보고하고 사용자 판단을 기다린다.
- 이미 목표 구성만 있으면 점검 결과만 보고한다. 반복 호출로 같은 파일을 복제하거나 빈 지침·기억을 만들지 않는다.

## 전환

- 먼저 필요한 지침을 읽은 뒤 표의 파일·디렉터리를 이동한다. 수행 중인 이 스킬도 설정 디렉터리와 함께 이동하므로 이후에는 새 실제 경로를 사용한다. 외부를 가리키는 링크는 대상 원본을 옮기거나 수정하지 않는다.
- 본문에 남은 이전 지침 이름·설정 경로는 공통 대응 규칙으로 해석한다. **MEMORY·MEMO·STRUCTURE, 지침·스킬 본문과 README를 일괄 치환하거나 전환 이력을 쓰기 위해 변경할 필요는 없다.** 파일 내용과 기록은 그대로 보존하는 것을 기본으로 한다.
- 다른 플랫폼 전용 파일·폴더도 의미와 구조가 같고 대응이 확인된 단순 이름·위치 변경만 수행한다. 설정 JSON, MCP·hook, 사용자 정의 agent 형식, 모델·도구 이름은 명칭만 바꾸어 호환 처리하지 않는다. 보존한 채 추가 조정이 필요한 항목을 보고한다.
- 하네스 밖 사용자 설정, 연구 자료·코드·산출물, .git은 변경하지 않는다. 스킬명을 다시 정하거나 새 업무를 만들지 않는다. 요청 범위에 없는 커밋·푸시는 수행하지 않는다.
- 이동이 실패하면 성공한 항목과 남은 항목을 확인한다. 이번에 옮긴 파일을 안전하게 되돌릴 수 있으면 복구하고, 다른 변경을 덮어쓰는 복구는 하지 않는다. 완료 상태를 추정하지 않는다.

## 검증과 보고

원래 파일들이 목표 경로에 존재하고 내용·스킬 이름·보조 파일이 보존됐는지 확인한다. 이전 경로가 남았다면 충돌, 보존한 자료, 미완료 이동 중 무엇 때문인지 구분한다. 새 구성에서 공통 지침·스킬과 작업 기록을 실제로 찾을 수 있는지도 확인한다.

변경한 표준과 주요 경로, 검증 결과, 추가 조정이 필요한 항목을 간단히 보고한다. 런타임 인식은 파일 이동과 구분해 확인하고, 새 환경에서 세션을 다시 열거나 스킬을 갱신해야 하면 그 단계만 안내한다.
