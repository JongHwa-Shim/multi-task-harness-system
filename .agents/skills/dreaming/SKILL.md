# 메모리 dreaming

원기록과 현재 산출물을 바탕으로 기억을 재검토·정리하는 dreaming을 이 하네스의 로컬 파일에 적용한다. 먼저 하네스 루트의 AGENTS.md 또는 CLAUDE.md를 읽고 공통 플랫폼 경로 대응 규칙을 적용한다. 본문에 남은 지침 이름은 현재 운영 구성의 실제 파일로 해석하며, 현재 채팅의 메인 업무는 유지한다.

**파일 목록 탐색 전에 요청의 작업 범위를 확정한다.** 지정 작업의 경로는 루트 작업 목록이나 `tasks/` 바로 아래 폴더명으로 확인한다. 단일 작업 요청에서 하네스 전체를 재귀 탐색하지 않는다.

## Dreaming의 의미와 목적

Dreaming은 개별 작업 중에 단편적으로 쌓인 기록을 되짚어, 다음 작업에 사용할 기억으로 검증·통합·재구성하는 정리 과정이다. 당시의 판단이 현재도 유효한지, 기록 사이에 빠진 맥락이 있는지, 어떤 지식과 실패 교훈을 계속 활용해야 하는지 확인한다.

- **기억 검증:** 메모리의 주장과 사용자 결정·원자료·실행 결과를 대조하여 사실, 가설, 과거 상태와 현재 상태를 구분한다.
- **기억 통합:** 흩어진 결정·변경·실패 기록의 관계를 연결하고 중복 설명을 정리한다. 반복되는 실패나 판단에서 재사용할 교훈과 적용 조건을 정리하되, 새로 도출한 해석은 검증된 사실과 구분한다.
- **재개용 맥락 구성:** 장기 목표·핵심 조건, 현재 집중 항목·미해결 문제·다음 행동, 중요한 이력을 함께 보존하면서 기본 읽기 문서를 간결하게 만든다.
- **업무 간 연결:** 같은 결과를 서로 다르게 기억하거나 의존 버전이 어긋난 곳을 확인하고, 실제 반영 상태와 앞으로 반영할 사항을 구분한다.

정리 결과는 MEMORY.md의 장기기억·단기기억·작업 내역, 그 핵심을 요약한 MEMO.md, 실제 파일 위치를 안내하는 STRUCTURE.md에 반영한다. 상세 원본과 변경 이력은 보존하며, 해결하지 못한 차이는 미해결로 남겨 다음 에이전트가 무엇을 신뢰하고 무엇을 더 확인해야 하는지 알 수 있게 한다.

## 능동적인 제안

- 업무 수행 중 메모리 누락·충돌·오래된 상태를 발견하거나 dreaming이 필요하다고 판단하면, 이유와 권장 범위(특정 작업 또는 전체 작업)를 짧게 설명하고 사용자에게 능동적으로 제안한다.
- 사용자가 dreaming 실행을 요청하거나 제안에 동의하면 진행한다. 이미 요청·승인한 실행을 다시 확인하지 않으며, 단순 제안을 실행 지시로 간주하지 않는다.

## 대상 범위

- **사용자가 작업을 지정하면 해당 작업만 점검한다.** 공통 지침과 이 스킬을 읽는 것을 제외한 자료 조사·수정은 지정 작업 루트 내부로 한정한다. 다른 작업이나 외부 자료의 확인이 필요하면 그 의존성을 보고하고 범위를 임의로 넓히지 않는다.
- **작업 지정이 없으면 현재 메인 업무와 관계없이 모든 실제 작업을 점검하고 작업 간 관계까지 대조한다.** 루트 AGENTS.md의 작업 목록과 `tasks/`의 실제 구성을 함께 확인해 대상을 정한다. 작업을 찾지 못하거나 지정 대상이 모호하면 알리고, 다른 작업이나 전체 작업으로 대체하지 않는다.
- 이 스킬의 수정 대상은 범위 내 작업의 MEMORY.md·MEMO.md·STRUCTURE.md다. 연구 원본·코드·데이터·결과를 읽어 확인할 수 있지만, 기록을 맞추려고 원본이나 연구 조건을 바꾸지 않는다.
- 하네스 루트에 메모리·구조 문서를 만들지 않는다. 작업이 없으면 그 상태를 보고한다. 기존 작업의 필수 문서가 빠져 있다면 남아 있는 기록과 확인된 근거로만 초기화하고 복구하지 못한 범위를 명시한다.

## 점검

1. 각 작업의 AGENTS.md와 세 컨텍스트 파일을 읽고 목표·핵심 조건·현재 상태·결정·실패 교훈·입출력 버전·미해결 문제를 대조한다. 큰 기록은 구획별로 읽거나 작업별 subagent에 나누되, 요약만 보고 원본 점검을 생략하지 않는다.
2. 충돌이나 누락은 사용자 지시·결정 기록, 관련 자료·산출물·실행 로그 등으로 확인한다. 범업무 점검에서는 필요에 따라 하네스 git의 해당 경로 이력을 조회한다. 접근할 수 없는 대화나 실행 결과를 기억하는 것처럼 보완하지 않는다.
3. 범업무 점검에서는 생산 작업의 현재 채택 결과와 소비 작업이 **실제로 반영한 버전**을 비교한다. 업무마다 역할·시점·사용 버전이 달라 생기는 차이와 진짜 모순을 구분한다.
4. STRUCTURE.md를 실제 파일과 대조해 누락·이동·삭제·역할 변경을 확인한다. 작업 루트 기준 경로와 하네스 운영 파일 제외 원칙을 유지한다.

## 근거에 따른 동기화

- **MEMORY.md가 기억의 보존 원본이어도 항상 더 최신이거나 정확하다고 단정하지 않는다.** MEMO.md에만 있는 정보도 독립된 근거와 변경 경위를 확인한다. 파일 종류·수정 시각·여러 agent의 의견 일치만으로 어느 쪽이 맞는지 결정하지 않는다.
- MEMO.md의 정보가 근거로 확인되며 MEMORY.md에서 누락됐다면 MEMORY.md의 적절한 구획과 작업 내역에 반영한 뒤 요약을 맞춘다. 확인되지 않은 요약의 주장을 사실로 승격하지 않는다.
- MEMORY.md의 정보 중 작업 재개에 필요한 목표·조건·결정·실패 교훈·다음 행동 등이 요약에서 빠졌다면 MEMO.md에 보완한다. 원본의 모든 상세를 요약에 복제하지 않는다.
- 과거 기록과 현재 기록의 차이가 확인된 변경이라면 변경 흐름을 보존하고 현재 상태를 정리한다. 이전 기록을 지우거나 실패·미검증 상태를 성공·검증 완료로 바꾸지 않는다.
- 생산 작업의 새 결과가 확인되어도 소비 작업에 실제 반영되었다는 근거가 없으면 **새 버전 확인·반영 대기**로 기록한다. 코드나 논문에 적용·검증한 것으로 표시하거나, 모든 작업의 버전을 기계적으로 통일하지 않는다.
- STRUCTURE.md는 확인된 파일 위치와 역할에 맞게 갱신한다. 파일 이름만으로 용도를 지어내거나, 사라진 파일의 내용을 추정하지 않는다.

## 판별할 수 없는 충돌

**근거로 해결되지 않는 상충은 임의로 선택·병합·전파하지 않는다.** 해당 항목의 수정을 보류하고 양쪽 주장과 출처를 보존한다. 관련 작업의 MEMORY.md에 미해결 사항으로 기록하고 MEMO.md에도 불확실성을 표시하되, 어느 주장도 확정 사실로 승격하지 않는다.

사용자에게 아래를 간결하게 보고하고 해당 항목의 후속 조치를 기다린다. 독립적으로 판단 가능한 정리는 계속할 수 있다.

- 충돌하는 내용과 각 파일·구획·기록 시각
- 확인한 근거와 판별하지 못한 이유
- 영향을 받는 작업·산출물·후속 판단
- 해결에 필요한 사용자 결정이나 추가 자료

## 반영과 종료

- 작업별 지침을 적용하고 파일별 수정 담당자를 정한다. 범업무 작업을 subagent에 위임하면 담당 작업·읽기/쓰기 범위·작업 간 쟁점을 전달하고, 메인 agent가 근거와 결과를 통합한다. 같은 파일을 동시에 덮어쓰지 않는다.
- 쓰기 직전에 점검 이후의 변경이 있는지 확인한다. 다른 작업이 파일을 갱신했다면 최신 내용을 다시 읽고 차이를 재검토한다.
- 의미 있는 수정은 MEMORY.md의 작업 내역에 무엇을 왜 바꿨는지, 근거·영향과 실제 `YYYY-MM-DD HH:mm:ss KST`를 남긴다. MEMORY.md를 갱신하면 MEMO.md도 같은 작업에서 갱신하고 원본 갱신 시각을 표시한다.
- 이미 기록된 미해결 항목을 중복해서 쌓지 않는다. 새 근거나 변경이 없으면 파일과 갱신 시각을 불필요하게 바꾸지 않는다.
- 마지막에 수정된 문서들을 다시 대조한다. 확인한 범위, 해결·보완한 내용, 남은 충돌·미확인 범위를 보고한다. 미해결 사항이 있으면 전체 동기화가 끝났다고 보고하지 않는다.
