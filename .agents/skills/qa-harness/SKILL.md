# 하네스 사용 안내

사용자가 지금 하려는 일을 하네스에서 어떻게 요청하면 되는지 친절하고 간결하게 설명한다. 메인 업무를 유지하며, 설명을 위한 예시를 실제 실행 지시로 취급하지 않는다.

먼저 이 하네스의 AGENTS.md 또는 CLAUDE.md와 README.md를 읽고 플랫폼 경로 대응 규칙을 따른다. 이미 확인한 내용은 활용하되 질문과 관련된 현재 구성을 확인한다.

## 무엇을 확인할지

- **목적·구조·기록:** 공통 지침에서 작업 루트, MEMORY·MEMO·STRUCTURE, work/·results/, 하네스 git의 역할을 확인한다. 파일마다 무엇을 두는지 사용자의 업무에 맞춰 설명한다.
- **스킬:** 현재 스킬 루트의 실제 SKILL.md에서 이름·description을 확인하고, 질문한 스킬의 본문을 읽는다. 메타 스킬은 이름 접두사가 아니라 description의 안내로 구분한다.
- **현재 작업·자료:** 작업 목록과 실제 작업 루트를 대조하고 필요한 MEMO·STRUCTURE를 읽는다. 과거 결정·진행 상태의 상세가 필요하면 해당 MEMORY와 근거를 조회한다. 모든 작업의 상세 기록을 매번 읽지 않는다.
- 파일이 없거나 기록이 모순되면 확인한 사실과 부족한 맥락을 구분한다. 설치된 스킬과 현재 채팅에서 호출 가능한 스킬도 구분하고, 모르는 상태를 추정하지 않는다.

## 답변 방식

- 질문의 답을 먼저 말하고, 이해에 필요한 이유와 **바로 써 볼 수 있는 요청 예시 1~2개**를 붙인다. 짧은 사용법 질문에는 긴 구조 설명을 반복하지 않는다.
- 자연어 자동 업무 선택, 명시적 task- 스킬 호출, 같은 채팅의 업무 유지, 일시적 타 업무 위임을 구분해 안내한다. 아직 없는 작업을 이미 준비된 것처럼 소개하지 않는다.
- 빠른 시작은 사용자 상황에 맞춰 init-harness → 첫 업무 요청 → 필요할 때 dreaming 흐름으로 안내한다. 이미 구성된 하네스에서는 필요한 상담·수정만 안내하고 전체 재초기화를 권하지 않는다.
- 사용자가 하네스를 어떻게 써야 할지 혼동하거나 업무 구성을 함께 정하고 싶어 하면 현재 스킬 루트의 init-harness/SKILL.md를 읽고 상담을 이어간다. 사용자가 이미 말한 어려움과 맥락을 이어받아 같은 질문을 반복하지 않는다.
- 아래 예시를 현재 플랫폼·실제 작업·등록된 스킬에 맞게 바꿔 사용한다. 없는 작업명이면 예시임을 밝히고 생성 방법을 함께 알려 준다.

```text
/init-harness 연구 조사와 구현 업무를 함께 쓸 수 있게 안내해 줘.
/init-harness 논문 작성 업무를 추가하고 싶어. 기존 실험 결과를 어떻게 연결할지 제안해 줘.
/task-ideation 이전에 비교한 연구 후보의 미해결 쟁점부터 이어가자.
/dreaming 기록과 현재 결과가 맞는지 정리해 줘.
/switch-agent-platform Claude 구성으로 바꿔 줘.
```

## 안내와 실행의 경계

질의응답만 요청받으면 파일·메모리·설정을 생성하거나 수정하지 않는다. 누락된 필수 파일을 발견해도 그 상태를 보고한다. 업무·폴더·스킬 생성과 분리, 구성 수정은 init-harness의 제안·동의 절차로 이어간다. 이미 제시한 구체안에 동의받았다면 같은 범위를 반복 확인하지 않는다. 명시적인 dreaming·플랫폼 전환 요청은 해당 스킬의 범위와 절차를 따른다.
